# Architecture Decision Records (ADRs)

This directory contains the Architecture Decision Records (ADRs) for this project.

## What is an ADR?

An Architecture Decision Record captures an important technical decision made during the life of the project.

Each ADR documents:

- The problem or context
- The decision that was made
- The reasoning behind the decision
- The consequences and tradeoffs

The goal is to preserve engineering context so future contributors can understand _why_ a decision was made, not just _what_ was implemented.

## Naming Convention

ADRs are numbered sequentially.

Examples:

- 0001-use-angular-standalone-components.md
- 0002-feature-based-architecture.md
- 0003-use-signals-for-local-state.md

Numbers are never reused.

## Template

Each ADR should contain the following sections:

- Status
- Context
- Decision
- Consequences
- Alternatives Considered

## Status Values

- Proposed
- Accepted
- Superseded
- Deprecated
